# 第四章 检索增强生成（RAG）

## 4.1 RAG 的基本流程

检索增强生成通过检索外部知识来辅助大语言模型回答问题。一个完整的 RAG 系统分为离线索引和在线问答两个阶段。离线索引阶段包括：文档解析、文本分块、向量化和建立索引。在线问答阶段包括：接收用户问题、检索相关片段、构造提示词、调用大模型生成答案并附上引用。

与微调相比，RAG 的优势是知识更新快，只需替换知识库文件而不必重新训练模型；回答可以追溯到原文，便于核查；私有数据留在本地知识库中，不需要写入模型参数。

## 4.2 文档解析与分块

文档解析负责把 PDF、Word、PPT、表格等文件转换为结构化文本，并尽量保留标题层级、表格和图片说明。解析质量直接决定后续检索效果，扫描版 PDF 需要先做 OCR 文字识别。

分块（Chunking）把长文本切成较小的知识片段，片段是向量化和检索的基本单位。分块大小（Chunk Size）需要权衡：片段太小，容易丢失上下文，一个完整的知识点被拆散到多个片段中；片段太大，一个片段会混合多个主题，向量表示变得模糊，检索精度下降，同时占用更多上下文窗口。重叠比例（Overlap Ratio）让相邻片段保留部分重复内容，能够减少段落边界造成的信息割裂，常用取值为 10% 到 15%。

## 4.3 向量化与 Embedding 模型

Embedding 模型把文本转换为固定长度的稠密向量，语义相近的文本在向量空间中距离更近。本课程使用的 BGE-Large-ZH-v1.5 由北京智源人工智能研究院发布，输出向量维度为 1024，最大输入长度为 512 个 token，超出部分会被截断。这也是课堂演示中把 Chunk Size 设为 256 而不是 512 的原因：给标题、关键词等附加内容留出余量。

两个向量之间的相似度通常用余弦相似度计算，取值范围为 -1 到 1，越接近 1 表示语义越相似。

## 4.4 全文检索与混合检索

全文检索（关键词检索）基于词项匹配，常用 BM25 算法打分。BM25 综合考虑词频、逆文档频率和文档长度，对术语、人名、编号等精确匹配非常有效，但无法识别同义表达。向量检索擅长语义匹配，即使问题和原文用词不同也能找到相关内容，但对罕见专有名词和编号不够敏感。

混合检索把两种分数加权合并：最终得分 = 向量权重 × 向量相似度 + 关键词权重 × 关键词相似度，两个权重之和为 1。例如向量权重为 0.7 时，关键词权重就是 0.3。相似度阈值（Similarity Threshold）用于过滤得分过低的片段，低于阈值的片段不会进入大模型的上下文。

## 4.5 重排序

重排序（Rerank）是在初步检索之后，用更精细的交叉编码器模型对候选片段重新打分。交叉编码器把问题和片段拼接在一起输入模型，能捕捉两者之间更细致的关系，精度更高，但速度比向量检索慢很多，因此只对排名靠前的几十个候选片段使用。

## 4.6 RAG 效果评估

评估 RAG 系统需要分别评估检索和生成两个环节。检索环节常用命中率（Hit Rate）和平均倒数排名（MRR）：命中率是正确片段出现在前 K 个结果中的问题比例，MRR 是正确片段排名倒数的平均值。生成环节关注答案的忠实度（是否只依据检索资料回答）和相关性（是否回答了用户的问题）。建议先准备 20 到 50 个带标准答案的测试问题，每次修改分块或检索参数后重新跑一遍，用数据比较不同配置。
